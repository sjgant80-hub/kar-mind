kar-mind

A persistent, autonomous cognitive stack that composes verified memory organs into one runnable system — and structurally cannot publish or spend.

The brain is switched on

Every organ below was built and proven, but they were not joined: a person carried each result from one to the next, so the person was the wiring. Since 2026-10-01 the organs are joined into one loop, and nobody has to relay anything between them:

  1. The journal is Kar's working memory. Every session start reads the memory files, Kar's asks and the build queue into the persistent journal (through the real mind and its sealed, walled event log), and starts the session from the digest it reads back: the latest builds, what changed, the next build, and the decisions only Simon makes. brain.mjs holds that law; brain-cli.mjs is the glue.
  2. The direct line carries it. Every message to Kar's cockpit reads the brain fresh, on every tier, including the local model on this machine.
  3. The soul takes memory in live. A lesson written mid-day is swapped into the running soul at once, chunked as boot chunks it. No restart.
  4. The loop runs from the queue. The next build is the first open item in Simon's approved order whose prerequisites are done. Money, publishing and standing switches are named as his decisions and wait for him; nothing in the brain can act on one.

Simon's pattern: can Kar call his decisions?

Simon's call: "then my pattern". A director profile built from his own sessions: every moment he was asked to choose, what kind of decision it was, and what he said. It learns only from the decisions before 24 September and predicts the week after, sealed before scoring. A kind of decision he calls so predictably that it reaches 95% is named, and only named: whether it stops needing him is his switch. Money, posting on his behalf and anything destructive stay his, whatever the rate. His words never leave his machine; what is here is counts.

Kar watches himself: fewer repeat mistakes?

Simon's call: "next watch". The creature that looked at its own misreads found U→V sooner; this is the same move for Kar's direct line. Every answer it got wrong in a sealed run is read for its shape — a neighbouring number on a crowded line, a neighbouring build's name, a detour into tools, half of a pair — and the loop folds them into a playbook he reads before he answers: one rule per shape, ordered by how often, with his real misses as examples, rewritten after every run. The test: new questions of the same shapes, asked with and without it.

The seed's codec against Simon's 15×

Simon's call: "15x is there". The seed's memory law says compress by prime indices, and its primorial fold codec (a set over prime rings ⇄ one integer, lossless by unique factorisation — the encoding core of Thomas Frumkin's work) is the mechanism. A shared dictionary saves only what the reader already holds: the session start's reader holds the memory index, a running cockpit session holds the digest it was given, claudedidy and Kar both hold the memory index. So every real payload is coded against exactly that, decoded back to prove nothing was lost, and counted in Claude tokens on Simon's login, with his 15× sealed as the bar.

Sealed before any payload was counted (data/codec-prereg.json), with Simon's 15× as the bar. Being measured; the result lands here whichever way it goes.

kar-mind wires small, independently-gated memory organs into one mind. It perceives a fact, cross-checks it against independent sources, consolidates it into meaning, generates new facts and loops them back, and births new domains — through real organs, with every state change read from each organ's own count. Nothing here uses an LLM as a judge; every check is deterministic and re-runnable.

The organs

  • crystal — exact facts, no drift; a read never blends one source's value into another's.
  • octa — verify: cross-checks 3+ independent sources per field, refuses a panel of duplicates.
  • strand — the movement law: recall score, then promote / hold / decay / expire, then the shelf transition.
  • dodeca — meaning: cosine-embedding retrieval.
  • icosa — generate: a dream cycle infers new facts from repeated patterns and loops the best back.
  • tetra — birth: bounded new-domain detection (novelty threshold + hard capacity cap).

It survives a restart

Cognition is event-sourced: every state-changing verb records its cause. The log is sealed to disk with real gzip and a receipt hash over every field (tamper-refused on load), and on boot the organs replay it and reach identical counts — a write-ahead-log persistence architecture. A brand-new process boots from the durable file alone and comes back whole.

It runs its own loop

From one call, the run-loop pulls its own stimuli and drives the full cascade over and over, moving real organ state with no caller per step — governed by a safety cap, stopping on dead air rather than spinning, and persisting itself each beat.

The safety wall. The autonomous loop can perceive, verify, consolidate, dream, and route — all cognition, all reversible, all inside the mind's own walled memory. It cannot publish or spend: the loop has no path to any irreversible outside-world action, by construction. The export door stays doubly gated by a consent id and a path wall, and a test proves a full autonomous run writes no file.
