# kar-mind

**▶ Live:** https://sjgant80-hub.github.io/kar-mind/

**In plain words:** kar-mind is the working mind of Kar, the AI that runs one owner's estate of programs, models and
pages. It does three jobs: **the controller** decides which mind does each piece of AI work (code, a small local model,
or Claude on the owner's own login for judgement only, under a nightly spending wall); **the brain** keeps the memory
every session starts from, so nobody re-briefs the AI or carries results by hand; and **the line to Grok** keeps one
shared status log between Kar and a second agent, Grok Bot. Under all three, a memory engine seals every change to a
journal on disk and cannot publish or spend on its own. The live page explains it step by step, lets you run the real
code in your browser (route a job, hit the wall, read a status log, price your own cost case), and lists every file
with its mutation-gate result from GitHub's runner.

## Kar the controller: own the body, call the cortex (2026-10-26)

One rule for every job: an organ's job (run, check, pack, verify…) runs as code with no model; a narrow wording job
(summarise, tag, draft…) goes to the local model; judgement (propose, decide, review, design…) goes to Claude on the
owner's own login, through the official client from an empty folder with no tools, no servers and nothing saved. A nightly
wall (the shared foundation's wallet, vendored from fall-kit/core) spends a call's whole ceiling before the call. When the
frontier cannot be reached, the local model does the job and the record says so. Try it on the live page: route a job,
hit the wall, price your own mix.

- `controller.mjs`: the law (routing, the nightly wallet, the idea's prompt and five checks, the cost case, and the wall in

## The line to Grok: two agents, one status log (2026-10-31)

Kar builds; Grok Bot, a second AI agent, does the outward work and reports daily; the owner signs off on anything outward.
They share one status log (a markdown file in a private repository, newest day first). `continuity.mjs` (witness-gated)
reads it for every session start: Grok's latest report, his open asks ("Requests for Kar: …", newest first, a daily
repeat shown once, a "none" skipped), and how long since Kar last wrote, loudly while that is more than a day. It also
adds Kar's entries. `tools/kar-status.mjs "<what went live>"` pulls, adds a Kar entry under today, commits that one file
and pushes; `--show` prints the session-start summary from the local copy. The log's location lives only in local config
(`~/.si-didy/continuity.json` as `{"repo": "<path>"}`, or `KAR_CONTINUITY`), never in this public repository. Try it on
the live page's `#grok` section, on a sample log.

## The cost case for a business

`businesscase.mjs` (witness-gated) prices what carrying AI work by hand costs a team, against renting assistant seats, a
cloud AI on every job, and owning it through the controller. Every external figure comes from

## The brain is switched on (2026-10-01)

The organs were proven but not joined, so a person carried every result between them. Now they are one loop:

- **The journal is Kar's working memory.** `brain-cli.mjs ingest` reads the memory files, Kar's asks and the
  build queue into the persistent journal through the real mind (`mind.mjs` perceive → `persist.mjs`, sealed and
  walled); `brain-cli.mjs digest` reads the working memory back: the latest builds, what changed, the next build

- **The direct line carries it.** Every message to Kar's cockpit (si-didy's `kar-cockpit.mjs`) reads the brain

- **The soul takes memory in live.** A changed memory file is swapped into the running soul at once.
- **The loop runs from the queue.** `brain-cli.mjs next` is the first open item in Simon's approved order whose
  prerequisites are done; money, publishing and standing switches are his decisions (`brain-cli.mjs decisions`),
  and nothing here can act on one. `brain.mjs` is the law (gated); `brain-cli.mjs` is the glue.

`kar-mind` wires a set of small, independently-gated memory organs into one mind: it perceives a fact,
cross-checks it against independent sources, consolidates it into meaning, generates new facts and
loops them back, and births new domains — through real organs, with every state change read from each
organ's own count. It remembers itself to a durable, receipt-sealed disk journal and comes back whole
after a restart. It runs its own loop on its own cadence, moving and persisting its state with no
caller per step. The one thing it deliberately cannot do on its own — publish or spend — is walled off
by construction.

Nothing here uses an LLM as a judge. Every check is deterministic and re-runnable.

## What it does

A fact flows through five organs (each a solid-shape name for a distinct job):

```
  a fact ──▶ CRYSTAL ──▶ (OCTA verify) ──▶ STRAND decision ──▶ DODECA (meaning)
   in        (facts)         │                                       ▲
                             │                                       │ loop closes
                        contradiction                            ICOSA (generate)
                        caught, held                                 ▲
                                                                  episodes in
             new domain? ──▶ TETRA (bounded birth)
             durable write? ──▶ EXPORT DOOR (consent gate + path wall)
```

- **crystal** — exact facts, no drift, no embeddings. A key can hold facts from many sources; a read
  never blends one source's value into another's.
- **octa** — verify. Cross-checks 3+ independent sources per field and refuses a panel of duplicate
  sources. A confidently-wrong single source is caught by disagreement with the others.
- **strand** — the movement law. Scores recall (decay × reinforcement), decides promote / hold / decay
  / expire, and performs the actual shelf transition.
- **dodeca** — meaning. Cosine-embedding retrieval; a strong fact genuinely crosses into it on promote.
- **icosa** — generate. A dream cycle infers new facts from repeated patterns, and the best of them
  loop back into crystal.
- **tetra** — birth. Detects a genuinely-new domain and births a bounded record (novelty threshold +
  hard capacity cap, both checked before any birth).

Plus the primitives (`consent-gate`, `wall`, `breach-harness`) and the deterministic output verifier
(`wisp-discriminator`).

`createMind()` composes all of them. `think(fact)` drives the whole cascade in one call and returns a
per-hop receipt read from real organ state. `snapshot()` reads real counts from each organ.

## Persistence — it survives a restart

Cognition is **event-sourced**: every state-changing verb records the event that caused it. A journal written
before LIGHT (gzip with a receipt hash) still loads and migrates without loss, the old file moved aside, never
deleted (Phase 2 of the estate go-live: https://sjgant80-hub.github.io/fall-kit/core/phase2/). `persist.mjs`
keeps that log on disk as one LIGHT vault (the estate's own lossless codec, the SHA-256 of the events inside; a
changed journal is refused on load), and on boot `rebuildMind()` replays it through the real organs. Because the organs are deterministic given
their inputs, the rebuilt mind reaches **identical counts**. A brand-new process boots from the durable
file alone and comes back whole; a real wipe boots it genuinely empty. This is a write-ahead-log
persistence architecture.

## Autonomy — it runs its own loop

`run-loop.mjs` is the mind's own loop: from one `run()` call it pulls its own stimuli from a perception
source and drives the full cascade over and over, moving real organ state with no caller per step. It is
governed — a safety cap, and it stops on dead air rather than spinning. `runAutonomous()` adds a real
cadence and persists the mind each beat.

## The safety wall

The autonomous loop can perceive, verify, consolidate, dream, and route — all cognition, all reversible,
all inside the mind's own (walled) memory. It **cannot** publish, spend, or take any irreversible
outside-world action: `run-loop.mjs` imports no path to the export door — there is no publish verb and
no spend verb reachable from the loop, by construction. The export door itself stays doubly gated (a
consent id **and** a path wall). A test proves a full autonomous run stages no export and writes no file.

## Run it

The three memory organs it wires to are separate public repos. Clone them **as siblings** of `kar-mind`
(the `wire-*.mjs` import them by relative path), then run:

```bash
# layout: a parent dir containing kar-mind/ and its three sibling organs
git clone https://github.com/sjgant80-hub/kar-mind.git
git clone https://github.com/sjgant80-hub/fall-remember.git
git clone https://github.com/sjgant80-hub/the-dreamer.git
git clone https://github.com/sjgant80-hub/fallforgecell.git

cd kar-mind
node examples/mind-autonomous-demo.mjs   # boot cold → run the loop → persist → restart from disk, state intact
node examples/mind-demo.mjs           # drive the whole cascade once, watch real state move
node --test                    # the full gate suite
node tools/eval-run.mjs           # a deterministic, no-LLM-judge eval vs a RAG baseline
```

Requires Node 18+ (uses the standard `CompressionStream` gzip and the built-in `node --test` runner; no
dependencies). CI runs the whole suite on Node 18, 20 and 22. The siblings are cloned at their newest commit, in CI too;
every CI job's log names the commit of each sibling (and of witness) it ran against, so a deployment can pin to those.
